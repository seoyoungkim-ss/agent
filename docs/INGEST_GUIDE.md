# 주간식단표 · 맛평가 · 취식현황 ingest 가이드

`docs/DEPLOYMENT.md` 6단계("데이터 수집 도구 설치")를 이미 마쳤다는
전제로, 실제 원본 엑셀 파일을 서버에 넣는 방법을 다룬다.

## 0. 엔드포인트는 2개뿐 — "맛평가"와 "취식현황"은 합쳐서 들어간다

헷갈리기 쉬운 부분: 백엔드 `/ingest/*`는 `weekly-menu`와 `meal-log`
**딱 2개**다. "맛평가 결과"와 "취식현황"은 서로 다른 API가 아니라,
**같은 `meal-log` 하나**로 합쳐서 들어간다 — POS 취식정보(취식현황)와
맛평가 리스트(맛평가) 두 원본 파일을 `ingestion-tool`이 로컬에서
병합한 뒤 한 번에 전송하는 구조다.

| 원본 파일 | 들어가는 곳 |
|---|---|
| 주간식단표 (xlsx) | `weekly-menu` |
| 식당취식정보(POS) + 맛평가 리스트 (xlsx 2개) | `meal-log` (내부 병합) |

## 1. 사전 준비

- Windows PC에 Excel + 나스카(DRM) 클라이언트가 설치돼 있어야 원본
  파일을 열 수 있다.
- `ingestion-tool/config.json`(`config.example.json` 복사) 값 확인:
  ```json
  {
    "backend_base_url": "http://<서버 IP>:8000/api",
    "api_token": "<서버 backend/.env의 INGEST_API_TOKEN과 동일한 값>",
    "employee_mapping_path": "",
    "verify_ssl": true
  }
  ```
  `api_token`이 서버와 다르면 전송 시 401이 난다.

## 2. 원본 파일 3종의 컬럼 매칭 확인

전송 전에 실제 파일을 열어 아래 헤더가 있는지 대조한다. **컬럼
순서는 상관없고(헤더 이름으로 매칭), 헤더 이름이 정확히 일치해야
한다**(공백은 무시하고 비교하므로 "Knox ID"/"KnoxID"는 같게 취급됨).

### 주간식단표
표 형태 그리드 — 컬럼 순서 고정(이름이 아니라 위치로 읽음):
- **A열**: 식사구분 — 정확히 `조식`/`중식`/`석식` 중 하나(병합 셀이면
  빈 칸은 위 값을 그대로 이어받음)
- **B열**: 코너명(마찬가지로 병합 셀 이어받음)
- **C~I열**: 헤더 행에 `월 화 수 목 금 토 일`이 있어야 함(7개 중
  **5개 이상 정확히 일치**해야 그 행을 헤더로 인식 — 하나둘 비어
  있어도 괜찮음)

셀 안에 메뉴가 여러 개 있으면 줄바꿈/쉼표(`,`)/슬래시(`/`)/가운뎃점
(`·`)으로 나뉘고, **첫 항목이 메인, 나머지가 부찬**으로 자동 분류됨.

### 식당취식정보(POS, 취식현황)
헤더 **이름**으로 매칭(순서 무관). 실제 파일엔 25개 안팎 컬럼이
있을 수 있지만, 그중 아래 16개가 있어야 한다:

```
일시, 부문명, 사업장명, 회사, 사원번호, 회사구분, 급식업체, 식당,
코너, 식구분, 포장구분, 메뉴명, 화면표시명(한글), 영수증번호, 구분,
정정여부
```

- `구분`(상태) 값이 **"정상"이 아닌 행은 기본적으로 제외**된다(취소/
  정정 등).
- `메뉴명`(코드성 이름)과 `화면표시명(한글)` 둘 다 있어야 하고, 실제
  meal_log에는 `화면표시명(한글)` 쪽이 들어간다(아래 맛평가 매칭에도
  이 값이 쓰임).

### 맛평가 리스트
헤더 위에 "식당 평가 리스트" 같은 제목 행이 한 줄 더 있어도 자동으로
헤더 행을 찾는다. 필수 헤더 5개:

```
취식일자, KnoxID(또는 "Knox ID"), 식사구분, 평가, 메뉴명
```
(`의견`, `평가의견`은 있으면 코멘트로 합쳐 쓰고 없어도 무방)
`평가` 값은 **`맛남`/`보통`/`개선`** 세 값만 유효하고, 취식일자는
**날짜만**(시간 정보 없음).

### (선택) 사번↔KnoxID 매핑 CSV
POS 파일의 사원번호와 맛평가 파일의 KnoxID가 값 체계부터 다른 회사
인원(B/C/D사 등)이 섞여 있으면 매핑이 필요하다. 헤더: `사번,knox_id`.
경로를 `config.json`의 `employee_mapping_path`에 지정.

> ⚠️ 맛평가는 (사번→변환된 knox_id, 취식 날짜, 식사구분,
> **화면표시명(한글)**) 조합으로 POS 기록과 매칭된다. 두 파일의 메뉴
> 표기가 다르면(예: 한쪽은 "제육볶음", 다른 쪽은 "제육볶음(매운맛)")
> 매칭이 안 되고 "미평가"로 남는다 — 실물 데이터로 매칭률을 꼭
> 확인할 것(아래 3단계 출력에 매칭률이 바로 나온다).

## 3. 실제 ingest 명령어

```powershell
cd ingestion-tool
.venv\Scripts\activate

REM 주간식단표
python cli.py weekly-menu "C:\경로\주간식단표.xlsx" --week-start 2026-08-24

REM 맛평가 + 취식현황 (반드시 두 파일을 함께 지정 — 순서: 취식정보 먼저, 맛평가 다음)
python cli.py meal-log "C:\경로\POS_취식정보.xlsx" "C:\경로\맛평가리스트.xlsx"
```

옵션:
- `--sheet NAME` (weekly-menu), `--transaction-sheet`/`--taste-sheet`
  (meal-log) — 시트가 첫 번째가 아니면 지정.
- `--yes` — 미리보기 확인(`y` 입력) 없이 바로 전송(자동화용).

두 명령 다 전송 전에 미리보기를 보여준다. `meal-log`는 특히 이런
출력이 나온다:
```
취식기록 1234행, 맛평가 987행 → 병합 1234행
  맛평가와 매칭됨: 950행 (77%) / 미평가: 284행
```
매칭률이 예상보다 낮으면 위 "메뉴명 표기 차이" 문제일 가능성이 높다.

500행 단위로 나눠 전송하고, 네트워크 오류 시 자동 재시도(최대 4회)
한다 — 큰 파일도 한 번에 돌리면 된다.

## 4. 전송 후 확인

서버에서 바로 재계산 트리거(데이터가 배치 전에도 바로 반영되게):
```bash
curl -X POST "http://<서버 IP>:8000/api/analysis/menu-performance/recompute?period_start=2026-01-01&period_end=2026-08-24"
curl -X POST "http://<서버 IP>:8000/api/analysis/users/taste-profile/recompute"
```
대시보드에서는 "메뉴 편성·운영" 탭(주간식단표 반영 확인)과 "현황"
탭(취식현황·만족도 반영 확인)에서 방금 넣은 날짜로 이동해 눈으로
확인한다.

## 5. 자주 막히는 지점

| 증상 | 원인 |
|---|---|
| `weekly-menu`가 "파싱된 행이 없습니다" | 요일 헤더(월~일)가 5개 미만 인식됨 — 병합 셀 때문에 헤더 행 자체를 못 찾는 경우가 흔함. 헤더 행 근처 병합을 풀어보고 재시도 |
| `필수 컬럼을 찾지 못했습니다: [...]` | POS/맛평가 파일의 헤더 이름이 위 표와 한 글자라도 다름(오타, 다른 표현) — 대소문자/공백은 자동 무시되지만 그 외엔 정확히 일치해야 함 |
| 맛평가 매칭률이 낮음 | POS의 `화면표시명(한글)`과 맛평가의 `메뉴명` 표기가 서로 다름 — 3단계 참고 |
| 건수가 예상보다 적음 | POS 파일의 `구분`이 "정상"이 아닌 행(취소/정정)은 기본 제외됨 |
| 전송 시 401 | `config.json`의 `api_token`이 서버 `.env`의 `INGEST_API_TOKEN`과 다름 |
| B/C/D사 인원 맛평가가 전부 미평가로 남음 | 사번↔KnoxID 값 체계가 다른데 매핑 CSV(`employee_mapping_path`)를 안 넣음 |

## 참고: API를 직접 호출해 테스트하고 싶을 때 (DRM 없는 정제 데이터 한정)

원본 파일 없이 이미 정제된 값 몇 건만 테스트로 넣어보고 싶으면
curl로 직접 가능하다(운영에선 위 CLI 플로우를 쓴다):
```bash
curl -X POST "http://<서버 IP>:8000/api/ingest/weekly-menu" \
  -H "Authorization: Bearer $INGEST_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"rows":[{"plan_date":"2026-08-24","meal_type":"중식","corner_name":"한식","menu_name":"제육볶음","menu_role":"메인","source_row_raw":"제육볶음"}]}'

curl -X POST "http://<서버 IP>:8000/api/ingest/meal-log" \
  -H "Authorization: Bearer $INGEST_API_TOKEN" -H "Content-Type: application/json" \
  -d '{"rows":[{"eaten_at":"2026-08-24T11:52:00","employee_id":"E12345","meal_type":"중식","corner_name":"한식","taste_score":"맛남","comment":"맛있어요","company_name":"삼성전자","menu_name":"제육볶음"}]}'
```
